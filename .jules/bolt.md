## 2025-03-05 - Redundant Array Traversals in Report/Result Aggregation
**Learning:** Found a specific anti-pattern in `packages/browsecraft-runner/src/scheduler.ts` and `result-aggregator.ts` where multiple stats computations (e.g. `passed`, `failed`, `skipped`) on array results were executed via chained `Array.filter().length` and `Array.reduce()`. These multiple traversals (N+1 arrays iterations) allocate unnecessary memory and block execution on the event loop for CPU bound metric gathering.
**Action:** When gathering multiple subsets of metrics or multiple aggregate lengths (like failed/passed counts or subsets) from an array, collapse all chained `.filter` and `.reduce` functions into a single O(N) `for...of` loop to eliminate redundant garbage collection and array traversal.
