## 2024-05-18 - Optimized auto-wait engine by skipping expensive layout reads during polling
**Learning:** In the core auto-wait engine (`waitForActionable`), computing rich element state (`innerText`, `boundingClientRect`, `className`, etc.) on every polling iteration causes unnecessary performance overhead, as this detailed state is only needed for error reporting when the actionability check ultimately times out, or at the very end when returning the final state.
**Action:** Introduced a `returnState` boolean flag to the `checkActionability` function that bypasses computing and returning the full `ElementState` during the polling phase (`returnState: false`). The full state is now only fetched once upon successful actionability, or when an error is caught due to a timeout, significantly reducing JavaScript execution time inside the browser during typical auto-waits.
